# 1 绪论

## 1.1 项目背景及意义

### 1.1.1 项目背景
当前智能家居正朝着 “智能化、场景化、健康化” 方向发展，但传统家居系统存在功能单一（多仅覆盖安防或环境监测）、交互不便（依赖按键 / APP）、数据孤岛（设备间联动弱）、健康维度缺失等问题；同时边缘计算与 AI 视觉技术的成熟，为家居场景下的 “本地智能 + 云端协同” 提供了技术基础，用户对 “安全防护 + 健康管理 + 便捷控制” 一体化家居系统的需求日益提升。

### 1.1.2 项目意义
1. **功能融合，提升家居体验：** 整合安防监测、环境感知、健康采集、智能控制等功能，实现 “居家 / 离家” 双模式、多控制方式（手势 / APP / 手动），解决传统家居系统功能割裂的痛点，让家居管理更便捷。
2. **技术落地，推动边缘智能普及：** 基于 X-CUBE-AI 实现 AI 手势识别的边缘端部署（INT8 量化加速），结合多传感器融合技术，降低 AI 与物联网技术在家庭场景的应用门槛，为边缘智能家居提供可参考的技术方案。
3. **安全健康双守护，强化居家保障：** 既通过多维度安防（指纹 / 超声 / 视觉）降低入侵误报率，又实现心率血氧、环境参数的实时监测与异常告警，填补了传统家居系统 “健康管理” 的空白，提升居家安全性与健康关怀。
4. **云端协同，实现智能化管理：** 借助OneNET云平台完成数据存储、远程监控与消息推送，结合本地 Flash 存储配置，兼顾 “本地实时响应” 与 “云端全局管理”，提升系统的可靠性与扩展性。

## 1.2 国内外研究现状
当前国内外智能家居安防与健康系统的研究，均聚焦 “边缘智能 + 多维度融合 + 云边协同” 的技术方向，但存在差异化特点：

国外：技术更侧重无感化监测、轻量化 AI 的成熟落地，在非接触式健康检测（如无线信号生命体征监测）、边缘 AI 模型的商业化应用（如谷歌、亚马逊的终端手势 / 行为识别）上领先，但本土化场景适配不足。国内：更聚焦功能整合与低成本工程化，通过物联网平台实现设备规模化接入，同时探索多模态安防（如本项目的 “指纹 + 超声 + 视觉”）、本地化通信（蓝牙近场配网）等场景创新，但在无感化健康技术、AI 模型自主轻量化能力上仍有短板。

整体来看，行业正从 “单一设备智能” 向 “系统级安全健康守护” 升级，而本项目的 “多传感器融合安防 + 边缘 AI 手势控制 + 健康数据本地 - 云端同步”，是对当前国内外技术方向的综合落地与局部创新。

### 1.2.1 国内研究现状
1. **安防与健康的系统集成**
   国内更侧重**本土化场景的功能整合**：小米、华为等企业推出 “智能门锁 + 摄像头 + 健康传感器” 套装，支持指纹 / 人脸双认证 + 心率血氧监测，但健康数据多依赖云端处理；本项目采用的 “指纹 + 超声 + AI 视觉” 多模态安防方案，在误报率优化（入侵置信度评分）上属于国内前沿探索。
2. **边缘计算与 AI 推理落地**
   AI 边缘推理技术快速普及：依托 STM32、ESP32 等低成本芯片，国内开发者通过 X-CUBE-AI 等工具实现 PyTorch 模型的终端部署，支持手势识别、异常行为检测等功能；但在模型轻量化（如 INT8 量化加速）的工程化应用上，与国外仍存在一定差距。
3. **物联网平台与本地化通信**
   OneNET、华为云 IoT 等平台已实现**MQTT 协议的大规模设备接入**，支持传感器数据上报、远程控制；同时，国内企业探索 “蓝牙近场通信 + 本地 Flash 存储” 方案（如本项目的配网 / 控制功能），解决网络中断时的设备离线可控问题。

### 1.2.2 国外研究现状
1. **智能家居安防与健康融合**
   国外聚焦**无感化健康监测 + 主动安防**的技术突破：例如 MIT 开发的 Vital-Radio 技术，通过无线信号实现非接触式心率、呼吸监测，精度达 99%，已应用于老人居家监护场景；谷歌 Nest 系列则整合 AI 视觉与环境传感器，实现 “行为异常检测 + 环境参数联动”，支持火灾、入侵的多维度预警。
2. **AI 边缘计算与交互技术**
   头部企业推动**轻量化 AI 模型的边缘部署**：苹果 HomeKit、谷歌 Home 支持基于终端设备的手势识别（如隔空操控智能家电），采用 INT8 量化等技术降低算力需求；同时，亚马逊 Ring 系列通过 “云端训练 - 边缘推理” 架构，实现本地端的人体姿态识别与实时告警。
3. **多传感器融合与云端协同**
   多传感器融合技术成熟度较高：例如博世、英飞凌的毫米波雷达 + 视觉传感器方案，可穿透障碍物实现人体生命体征监测；云端层面，亚马逊 AWS IoT、谷歌 Cloud IoT 采用 MQTT 协议构建 “设备 - 边缘 - 云端” 三级架构，支持海量设备的低延迟通信与数据同步。

# 3 系统硬件及软件设计

## 3.1 MQ-2气体传感器部分（李成基）

### 3.1.1 介绍
MQ-2气体传感器是一种常用的气体传感器，用于检测空气中的烟雾浓度。工作原理是基于半导体气敏元件的电阻变化。当烟雾气体进入传感器时，它会与气敏元件表面的敏感材料发生化学反应，导致电阻值发生变化。通过测量电阻值的变化，可以推断出烟雾浓度的大小。

![MQ-2气体传感器实体图](path/to/image.png)
**图 3-1 MQ-2气体传感器实体图**

![MQ-2气体传感器原理图](path/to/image.png)
**图 3-2 MQ-2气体传感器原理图**

**工作原理介绍：**
使用MQ-2型烟雾传感器属于二氧化锡(SnO2)半导体气敏材料，属于表面离子式N型半导体。处于200~3000摄氏度时，二氧化锡表面吸附空气中的氧，形成氧的负离子吸附，使半导体中的电子密度减少，从面使其电阻值增加。当与烟雾接触时，如果晶粒间界处的势垒收到烟雾的调至面变化，就会引起表面导电率的变化。利用这一点就可以获得这种烟雾存在的信息。烟雾浓度越大导电率越大，输出电阻越低，则输出的模拟信号就越大。

### 3.1.2 开发过程
1. **MQ-2传感器驱动头文件（mq2.h）核心说明**
    * **(1) 文件定位与作用**
        mq2.h 作为 MQ-2 烟雾传感器的驱动配置头文件，是传感器硬件与上层应用程序的接口层。核心实现硬件参数抽象化配置与功能函数标准化声明，既保证驱动代码的可移植性，也降低上层代码对硬件底层的依赖。
    * **(2) 关键配置与设计逻辑**
        * **模式宏定义（MODE）：** 通过 `define MODE 1` 实现传感器工作模式的一键切换（1为模拟AO模式，0为数字DO模式）。模拟模式下采集连续的浓度电压信号，数字模式下仅输出“超标/正常”的电平信号，适配不同精度需求的应用场景。
        * **硬件引脚宏定义：** 基于 MODE 的配置，分别定义模拟 AO 引脚（PA0，ADC通道0）、数字 DO 引脚（PA1）的时钟、端口、引脚号。所有硬件参数集中管理，修改时仅需调整宏定义，无需改动驱动实现代码，符合嵌入式开发“硬件与逻辑解耦”的设计原则。
        * **采集稳定性配置：** `define MQ2_READ_TIMES 10` 定义 ADC 采集次数，通过多次采集取平均的方式过滤模拟信号噪声，提升数据可靠性。
        * **函数接口声明：** 声明 `MQ2_Init()`（硬件初始化）、`MQ2_GetData()`（原始数据读取）、`MQ2_GetData_PPM()`（浓度值换算）3个核心函数，为上层代码提供标准化调用接口，隐藏底层硬件操作细节。
        * **头文件保护机制：** 通过 `ifndef __MQ2_H` 等指令防止头文件重复包含，避免编译阶段的变量/函数重复定义错误，符合 C 语言工程化开发规范。

2. **MQ-2传感器驱动实现文件（mq2.c）核心说明**
    * **(1) 文件定位与作用**
        mq2.c 是 mq2.h 声明接口的具体实现文件，基于 STM32F103ZE 芯片的硬件特性，完成传感器初始化、数据采集、浓度换算的底层逻辑封装，是传感器功能落地的核心载体。
    * **(2) 核心函数实现逻辑**
        * **MQ2_Init()：** 根据 `mq2.h` 的 MODE 配置分模式初始化硬件。
            * **模拟模式：** 将 AO 引脚配置为模拟输入模式，使能 ADC 时钟并完成 ADC 初始化与校准，保证模拟电压信号的有效采集。
            * **数字模式：** 将 DO 引脚配置为上拉输入模式，实现传感器数字电平信号的检测。
        * **MQ2_GetData()：** 核心数据读取函数，兼顾稳定性与场景适配。
            * **模拟模式：** 按 `mq2.h` 定义的采集次数（10次）循环读取 ADC 值，累加后取平均值，过滤模拟信号的随机噪声，返回 12 位 ADC 原始值（0~4095）。
            * **数字模式：** 读取 DO 引脚电平，通过电平取反转换为“0（正常）/1（超标）”的状态值，直观反映烟雾是否超标。
        * **MQ2_GetData_PPM()：** 仅模拟模式生效。基于 MQ-2 传感器的电压-浓度特性曲线，将 ADC 原始值转换为电压值，再通过传感器电阻（Rs）与洁净空气电阻（R0）的比值，拟合计算出烟雾浓度的 PPM（每百万分之一）值，实现从“原始电信号”到“直观浓度值”的转换，满足量化分析需求。

## 3.2 HC-05蓝牙部分（李成基）

### 3.2.1 介绍
HC-05是一款功能强大的经典蓝牙模块，由爱信电子（EGBT）生产。
它基于蓝牙2.0标准，支持多种传输协议，包括串口通信（UART）和蓝牙SPP（串口通信）。
HC-05可以在主设备模式（Master）或从设备模式（Slave）之间切换，具有较高的灵活性。
它支持蓝牙连接密码的设置，以提高安全性。
HC-05具有6个引脚，包括VCC（供电）、GND（接地）、TXD（发送数据）、RXD（接收数据）、STATE（状态）和EN（使能）。
STATE引脚可用于检测连接状态和模块工作模式。
HC-05可以通过AT指令进行配置和控制，例如更改蓝牙名称、波特率、配对密码等

### 3.2.2 开发过程
1. **连接硬件**
    * **(1) 电源连接**
        将 HC-05 模块的 `VCC` 引脚连接到 STM32 的 5V 电源引脚，`GND` 引脚连接到 STM32 的地引脚。
    * **(2) 串口通信连接**
        将 HC-05 模块的 `TXD` 引脚连接到 STM32 的 UART 接收引脚（例如 `USART1_RX`），`RXD` 引脚连接到 STM32 的 UART 发送引脚（例如 `USART1_TX`）。
    * **(3) AT 模式控制（可选）**
        如果需要进行模块的配置或进入 AT 命令模式，可以将 HC-05 模块的 `EN` 引脚连接到 STM32 的一个 GPIO 引脚，并在代码中控制该引脚的状态。
2. **STM32 串口底层配置（标准库）**
    * **(1) 时钟使能配置**
        通过标准库函数开启 USART1 及对应 GPIO 端口的时钟。
        * **时钟开启：** 开启总线的 USART1 时钟；使能 GPIOA 和 GPIOB 时钟，适配 PA9/PA10 引脚。
    * **(2) GPIO 引脚模式配置**
        将 PA9（TX）配置为“推挽复用输出模式”，PA10（RX）配置为“浮空输入模式”。
        * **PA9 配置：** 初始化 `GPIO_InitTypeDef` 结构体，设置 PA9 的模式为 `GPIO_Mode_AF_PP`（复用推挽输出），速度为 50MHz。
        * **PA10 配置：** 设置 PA10 的模式为 `GPIO_Mode_IN_FLOATING`（浮空输入），匹配串口接收的电平检测需求。
    * **(3) 串口核心参数配置**
        初始化 `USART_InitTypeDef` 结构体，严格匹配 HC-05 的通信参数。
        * **参数设置：** 波特率 `USART_BaudRate_9600`；数据位 `USART_WordLength_8b`；停止位 `USART_StopBits_1`；校验位 `USART_Parity_No`；模式 `USART_Mode_Tx | USART_Mode_Rx`（同时启用发送和接收）；流控 `USART_HardwareFlowControl_None`（无硬件流控）。
        * **参数写入：** 调用 `USART_Init(USART1, &USART_InitStructure)` 完成参数写入。
    * **(4) 串口中断配置**
        为实现数据的实时收发，配置 USART1 的中断控制器（NVIC）。
        * **全局中断：** 使能 USART1 的全局中断 `NVIC_EnableIRQ(USART1_IRQn)`。
        * **优先级配置：** 配置中断优先级（抢占优先级、响应优先级），确保串口中断不被其他低优先级中断阻塞。
        * **接收中断：** 启用串口接收中断 `USART_ITConfig(USART1, USART_IT_RXNE, ENABLE)`，当接收寄存器非空时触发中断。
        * **发送中断（可选）：** 启用发送完成中断 `USART_ITConfig(USART1, USART_IT_TC, ENABLE)`，用于发送完成后的状态判断。
    * **(5) 串口使能**
        调用 `USART_Cmd(USART1, ENABLE)` 激活 USART1，完成底层硬件配置。
3. **HC-05 通信功能开发**
    * **(1) 数据发送功能实现**
        基于标准库封装串口发送函数，支持单字节、字节数组、字符串发送。
        * **单字节发送：** 通过 `USART_SendData(USART1, data)` 发送单个字节，循环等待发送寄存器为空 `USART_GetFlagStatus(USART1, USART_FLAG_TXE)`，确保数据发送完成。
        * **字符串/数组发送：** 遍历待发送数据，逐字节调用单字节发送函数，适配 HC-05 的 AT 指令、自定义数据的发送需求（如发送 `AT+NAME=BLUETOOTH` 修改模块名称）。
    * **(2) 数据接收功能实现**
        通过中断服务函数实现异步接收，避免 CPU 轮询占用资源。
        * **中断服务函数：** 编写 `USART1_IRQHandler()`，当检测到“接收寄存器非空”中断时，读取接收数据 `USART_ReceiveData(USART1)`。
        * **接收缓冲区：** 设计接收缓冲区（如数组 `USART1_Rx_Buf`），将接收的数据存入缓冲区，并记录接收长度。
        * **接收完成标志：** 定义接收完成标志位（如 `USART1_Rx_Flag`），当检测到结束符（如换行符 `\n`）或缓冲区满时，置位标志位，通知主程序处理数据。
    * **(3) HC-05 AT 指令交互开发**
        基于上述收发函数，编写 HC-05 的配置逻辑。
        * **AT 指令模式触发：** 若接有 KEY 引脚，通过 GPIO 置高电平，延时后发送 `AT` 测试指令，验证模块是否进入 AT 模式（返回 `OK` 则成功）。
        * **常用指令封装：** 编写函数实现 HC-05 参数配置，如修改名称（`AT+NAME=XXX`）、修改波特率（`AT+UART=9600,8,1,0,0`）、查询配对码（`AT+PIN?`）等。
        * **指令响应解析：** 发送 AT 指令后，读取接收缓冲区的响应数据，解析 `OK`、`ERROR` 等关键字，判断指令执行结果。

## 3.3 GY30数字光强传感器检测与报警（李义旻）

### 3.3.1 介绍
![GY30数字光强传感器电路图](path/to/image.png)
**图 3-3 GY30数字光强传感器电路图**

**原理：** GY30光强传感器基于BH1750芯片实现数字式光照检测，其核心原理是利用内置光敏二极管阵列感应环境光子的光电效应——当光线照射时，半导体材料激发产生与光强成正比的微安级电流，该电流经芯片内部I/V转换电路转为电压信号后，直接由16位高精度ADC进行模数转换并量化处理，最终通过I²C数字接口直接输出以勒克斯（lux）为单位的数字量，无需外接ADC或复杂校准电路，具备响应快、功耗低、抗干扰强的特点。

### 3.3.2 开发过程
1. **硬件连接：** 
将STM32的GPIO引脚配置为开漏输出模式，连接GY-30模块的时钟线和数据线。
2. **IIC通信协议实现：** 
    * **(1)信号时序生成：** 通过精确微秒级延时产生起始和停止信号，确保总线状态转换符合协议标准
    * **(2)双向数据传输：** 动态切换数据线方向（输出/输入），实现主机发送命令和接收从机应答
    * **(3)数据收发机制：** 按位传输数据位，读取时先获取高8位数据，再读取低8位并组合成16位整型值
3. **传感器控制逻辑实现**
    * **(1)初始化序列：** 依次发送上电命令、复位命令、测量模式配置命令
    * **(2)数据获取流程：** 发送读地址请求后，连续读取两个字节的光照强度数据
4. **主循环处理：**
周期性获取16位原始数据，根据测量模式换算为实际光照强度值，通过串口输出验证结果
5. **对光强进行判断：**
当测得光强小于50lux时，代表烟雾浓度过高，蜂鸣器发出警报，LED灯常亮，当测得光强大于50lux时，蜂鸣器和LED关闭
